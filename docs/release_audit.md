# Phase 7 Public-Release Audit

## Scope

Reviewed application code, notebooks, source modules, documentation, reports, results, data directories, model artifacts, configuration, dependencies and generated/cache files before public release preparation.

## Privacy and repository hygiene

- No email address, phone number, API key, access token, password, private key or committed Streamlit secret was found.
- Application code contains no user-specific absolute path.
- `.env`, `.env.*`, `.streamlit/secrets.toml`, virtual environments, Python caches, notebook checkpoints, logs, editor temporary files and OS metadata are ignored.
- Local `.DS_Store` and `__pycache__` directories exist but are ignored and must not be staged.
- Public-release staging still requires a human review because the project directory has not yet been pushed as its own GitHub repository.

## Dataset distribution and licence

The dataset is documented as **River Water Quality Monitoring 1990 to 2024 — All Parameters**, Northern Ireland Environment Agency / DAERA, published through OpenDataNI under the UK Open Government Licence v3.0.

The OGL permits copying, distribution and adaptation subject to source acknowledgement. Attribution appears in the README, dataset documentation and application About page. The raw and full processed files remain excluded for repository size and reproducibility reasons, not because redistribution is claimed to be prohibited. The small derived app artifacts are generated by `scripts/build_app_artifacts.py`, with the source checksum and row counts recorded in `data/app/manifest.json`.

## Model and dependency compatibility

- The saved artifact reloads as the complete fitted Phase 4 pipeline and produces a finite prediction.
- The artifact's task, target and 25-feature order are validated on load.
- SHA-256 and verified scikit-learn/Joblib versions are documented in `models/README.md`.
- Direct dependencies are pinned; no transitive packages are manually pinned.
- Jupyter and Matplotlib remain because they are required by the reproducible research workflow even though the Streamlit UI does not import them directly.

## Scientific and consistency audit

- No public-facing claim classifies water as safe/unsafe, diagnoses pollution, forecasts future conditions, claims regulatory validity or treats feature importance as causation.
- Empirical error percentiles are described as validation summaries, not individual prediction/confidence intervals.
- Geographic and target-range limitations remain visible.
- Repeated metrics were checked against `results/phase4_summary.json`; no Phase 3/4 model, split or result was changed.

## Release conclusion

The files are prepared for manual public-release staging. Release is not complete until the author installs/configures Git LFS, reviews staged files, creates/pushes the GitHub repository, deploys the app and smoke-tests the public URL.
